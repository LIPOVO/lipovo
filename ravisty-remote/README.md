# Рависты Пульт для iPhone

Нативное SwiftUI-приложение для iOS 16+. Подключается напрямую к ADB TCP телевизора, исходно `192.168.0.121:5555`. Не требует HTTP-моста, компьютера при использовании, облачного сервиса или дополнительного фонового приложения на ТВ.

## Что есть

- D-pad, OK, Назад, Домой, громкость, выключение звука.
- Запуск Рависты TV, YouTube, Кинопоиска, VK Видео, Wink и AirScreen («AirPlay / Cast»).
- Редактируемые IP и порт, сохранённые только на iPhone.
- RSA-2048 ключ ADB в Keychain; подтверждение нового устройства на экране телевизора.
- Снимок через `exec:screencap -p`, с удалением только диагностического префикса MediaTek до PNG. Снимок остаётся в памяти приложения.
- Нет сторонних зависимостей, аналитики и сетевых обращений, кроме указанного телевизора.

## Статус проверки

Версия **1.2 (build 4)** проверена [на macOS в GitHub Actions](https://github.com/LIPOVO/lipovo/actions/runs/42368812622): Xcode 16.4, iOS 18.5, симулятор iPhone SE 3-го поколения. **Все 14 XCTest прошли, Release-сборка arm64 и проверка IPA завершились успешно.** Проверенная ревизия: `4138b916de07fdf3a0521f4a136ea82b02c7d7f2`. Тесты включают реальный loopback TCP-обмен с разными порядками ADB/helper-подтверждений, фрагментированными пакетами, обрывом потока без повторного нажатия и проверкой входных данных для запуска приложений.

Файл `RavistyRemote-1.2.ipa`: 258819 байт. SHA-256: `4a9f24f9a5aaf2cbe0b3eeaa45c7803e189a5d5fc75ba36b804d8bccc3945557`. Проверены структура Payload, 64-битный исполняемый файл arm64 и скомпилированные метаданные: `CFBundleDisplayName = Ravisty Remote`, `CFBundleName = RavistyRemote`, версия `1.2`, build `4`. ASCII-имена сохранены для совместимости с обработкой имени в AltStore. Это неподписанная IPA для подписи AltStore; **установку и поведение версии 1.2 на физическом iPhone ещё нужно подтвердить**.

Один процесс [помощника ввода](TVInputHelper/README.md) на ТВ обслуживает всю ADB-сессию, вместо запуска `app_process` для каждой кнопки. Файл помощника предварительно размещается в `/data/local/tmp/`; его процесс работает только пока открыто соединение пульта. Если помощника нет, используется обычная команда Android `input`. Для клавиш выделено отдельное соединение, поэтому снимок экрана не блокирует пульт. Очередь ограничена тремя ожидающими нажатиями, команды старше 350 мс отбрасываются; после ошибки подтверждения нажатие не повторяется автоматически. Добавлены `TCP_NODELAY` и измерение отклика. При уходе приложения в фон соединения закрываются, а при возвращении восстанавливаются только после ранее выбранного подключения; ручное отключение отменяет восстановление.

Raw Wi-Fi-проверка на этом BQ показала медиану 13,28 мс до подтверждения ввода помощником против примерно 1,9–2,0 с для нового `input keyevent`. Это время принятия пары DOWN/UP системой, а не полного отображения результата приложением и не замер на конкретном iPhone.

Отдельная read-only проверка протокола на данном BQ подтвердила CNXN с объявлением версии 1.0, корректные контрольные суммы и два последовательных запроса `getprop ro.product.model` в одном TCP-соединении. Сервер прислал повторный CLSE для предыдущего stream ID; клиент учитывает такие поздние пакеты. Это проверка формата обмена, а не запуск Swift-приложения.

## Сборка на Mac

Версия 1.2 добавляет запуск AirScreen и подсказки по повтору экрана iPhone, Google Cast и разделу «Музыка» в Кинопоиске. Запуск приложений сначала получает подходящий компонент через Package Manager и открывает его явно: это поддерживает телевизоры, на которых обычный неявный запуск Кинопоиска не срабатывает. Прямая музыкальная ссылка не используется.

Нужен Xcode с iOS SDK (проект использует deployment target iOS 16).

```sh
cd ios-remote
bash test-on-mac.sh 'platform=iOS Simulator,name=iPhone 16'
bash build-unsigned-ipa.sh
```

Имя симулятора замените на установленное, если нужно; список: `xcrun simctl list devices available`.

Второй скрипт собирает `build/RavistyRemote-unsigned.ipa` с `CODE_SIGNING_ALLOWED=NO`. Это **неподписанный** контейнер: обычная установка iOS его не принимает. Импортируйте в AltStore/AltServer для подписи своей учётной записью. Ключи Apple, provisioning profile и Apple ID не входят в проект.

Для запуска прямо из Xcode откройте `RavistyRemote.xcodeproj`, выберите свою команду в Signing & Capabilities и iPhone как устройство. Bundle ID по умолчанию `tv.ravisty.remote` можно заменить на свой.

## Подключение

1. iPhone и телевизор находятся в одной локальной сети. На ТВ включена отладка и доступен ADB TCP порт, по умолчанию 5555.
2. На iPhone разрешите приложению доступ к локальной сети, откройте карточку подключения и нажмите «Подключить».
3. При первом соединении разрешите ключ iPhone в запросе отладки на экране ТВ. Ключ отличается от ключа компьютера; прежнее разрешение для ПК его не заменяет.
4. После соединения используйте кнопки пульта. Снимок запрашивается отдельной кнопкой.

Реализован классический RSA ADB TCP. Android Wireless Debugging с шестизначным pairing code/TLS здесь не реализован. Этот BQ уже предоставлял классический ADB на 5555. Если адрес изменился после перезапуска роутера, поправьте его в приложении. Команды запуска предполагают, что указанные пакеты уже установлены на ТВ.

Legacy ADB не шифрует транспорт; используйте доверенную локальную сеть. Приложение не включает ADB и не меняет режим отладки самостоятельно.

## Протокол и тесты

Клиент обрабатывает CNXN, AUTH, OPEN, OKAY, WRTE и CLSE с ограничением размеров, тайм-аутами, последовательной обработкой команд и суммой байтов в заголовке. Для совместимости объявляет ADB protocol 1.0 и maxdata 4096. RSA-токен подписывается как уже готовый SHA-1 digest, без повторного хеширования.

Тесты проверяют упаковку/проверку пакетов, отказ на испорченных и слишком больших пакетах, кодирование Android public key (включая `n0inv` и `R² mod n`) и безопасное выделение PNG. Тесты не заменяют проверку NWConnection, экрана разрешения и пульта на реальном устройстве.

Первичные источники:

- [AOSP ADB protocol](https://android.googlesource.com/platform/system/core/+/android10-release/adb/protocol.txt)
- [AOSP Android RSA public-key format](https://android.googlesource.com/platform/system/core/+/refs/heads/main/libcrypto_utils/android_pubkey.cpp)
- [Apple SecKeyCreateSignature](https://developer.apple.com/documentation/security/seckeycreatesignature(_:_:_:_:))

Код написан для этого проекта; алгоритм кодирования реализован по формату AOSP, без сторонней криптобиблиотеки. Приватный ключ не экспортируется из Keychain приложением.
